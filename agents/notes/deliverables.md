# 交付物寫法

報告、文件、PR 內文、計畫、PDF 這類交付物的共同規則。`agents/AGENTS.md` 的回覆規則（白話、不公文腔、精簡時刪掉沒價值的段落，不是把每句都砍短）同樣適用於交付物。

- 寫成一份自己就完整的最終版：只讀這一份就夠，不用知道它是怎麼改過來的。
- 收到意見就直接改內容本身，不留草稿、版本、第幾輪修改、原本寫法這類修訂痕跡，也不在文件內自建修訂記錄或版本章節；版本歷史交給 git，沒被 git 追蹤的交付物要追版本就用檔名。
- 影響讀者判斷的限制、假設、取捨、失敗或略過的步驟要留著，審查者需要知道的決定也一樣。
- 只有使用者明確要 changelog 或修訂歷史時，才另外寫演變過程。
