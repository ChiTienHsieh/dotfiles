只有標題能幫助使用者看出下一步行動或應理解內容時才更新。

## 流程

1. 讀取 task 的最新狀態。若要替其他 task 改名，就在改名前重新讀取該 task。
2. 若準備把任一 task 標題開頭的狀態 emoji 改為 `📦`：
   - 若處理目前 task，從目前可用的 skills 清單取得名稱精確為 `wrap` 的唯一項目，完整讀取其 `SKILL.md`，只執行其中的「封存前檢查」流程；找不到、不唯一或缺少該流程時停止，檢查通過才可繼續。
   - 若處理其他 task，不得沿用目前 task 的檢查結果；只有重新讀取後確認該 task 的同等封存前檢查已通過，才可使用 `📦`。
3. 狀態標記只用於兩種例外：
   - `🚨`：使用者明確指定要親自持續追蹤的關鍵或高槓桿 task；標記與 pin 必須同步，且只由使用者明示新增或解除。
   - `📦`：沒有未完成責任或重要學習，值得封存。
   其他 active、waiting 或一般需要使用者注意的 task 都不使用狀態 emoji；用淺顯、簡短的標題本身說清楚範圍、目的與進度。
4. 若 agent 應繼續工作且標題仍準確，不改名。Stop、閒置、最後回覆或只有本機 commit，都不足以使用 `📦`。
5. `🚨` 與 `📦` 只能作為完整標題的前綴，不能代替標題。套用時替換既有的特殊標記，或在沒有時加到最前面；回到一般狀態時移除既有標記與舊的 `⏳`。保留原本的範圍與目的，只有目前進度已不正確時才更新最後一欄。不得把完整標題縮成單一 emoji。
6. 新增標題或需要完整改名時，使用以下精確格式：

   ```text
   <repo／project／最小可辨識範圍> | <使用者目的> | <進度>
   <🚨 或 📦，僅適用時> <repo／project／最小可辨識範圍> | <使用者目的> | <進度>
   ```

   只能有一行及兩個半形 ` | ` 分隔符。目標 24–32 字，最多 40 字；最後一欄必須反映目前進度。

7. 各自使用可用的改標題、pin 或 unpin 工具；每項只呼叫一次。目前 task 省略 `threadId`；經授權替其他 task 操作時，使用步驟 1 取得的精確 ID 與 host。若 `🚨` 標記與 pin／unpin 只有一項成功，重新讀取實際狀態並回報，不得假裝兩者已同步或盲目重試。
8. 缺少哪項工具，就明講該項仍需手動完成；缺少改標題工具時附上完整建議標題。不得重建舊 Stop hook、shell、app-server 或暫存檔等替代方案。

除了使用者明示的 `🚨` pin／unpin，不得封存、取消封存、刪除或改變其他 task 的狀態。`📦` 只代表建議使用者之後封存。

只在使用者單獨要求改名時簡短確認；作為其他工作的正常收尾時不另行報告。
