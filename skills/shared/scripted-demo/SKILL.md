# Scripted demo

做出來的東西是一個 HTML 檔，雙擊就能打開，看起來像一台影片播放器：深色外框包住亮色的被示範畫面（舞台），舞台正下方是深色控制列，有章節、旁白、上一步／播放／下一步、速度和進度條。按播放，假游標會照劇本一步一步點完流程，spotlight 把正在講的地方打亮、其他地方調暗。每段開頭有介紹卡、結尾有總結卡。觀眾也可以按「自己點點看」直接操作舞台。

這個做法的好處是：改文案只要改劇本裡的一行字，不必重錄影片；上一步、跳段、調速度都是免費附送；同一份檔案也可以拿來討論設計。

## 零件

| 零件 | 是什麼 | 誰負責 |
|---|---|---|
| 舞台 | 被示範的畫面，照一般網頁的寫法做 | 你寫 |
| 錨點 | 舞台上每個會被點、被框的元素掛 `data-demo="名字"` | 你寫 |
| 狀態與 render | 畫面完全由一個 state 物件決定；`render(state)` 把它畫出來 | 你寫 |
| 劇本 | 段落與步驟的資料：去哪個錨點、做什麼、旁白、狀態改了什麼 | 你寫 |
| 演員與播放器 | 游標、spotlight、旁白、卡片、深色控制列、上一步的重算、動畫取消 | `assets/player.js`，不要自己重寫 |

播放器已經解決了最容易出錯的部分：上一步怎麼退回、連按時舊動畫怎麼停、縮放後怎麼重新對準、游標怎麼不穿過暗處。重寫一份只會把這些坑再踩一次。控制列的外觀也一起包在播放器裡：深色控制、亮色內容，觀眾一眼分得出哪裡是遙控器、哪裡是節目。不要另外做側邊面板或浮動按鈕，那會讓畫面變躁；要配合品牌只改 CSS 變數（見參考文件）。

## 工作流程

1. **先問清楚三件事**：要示範哪個流程、給誰看、分成哪幾段。給一般人看的就用日常用語寫旁白，不用內部術語。
   - **比較設計方案時**：每個方案各自一段，一次只演一個方案，因為觀眾沒辦法同時專心看兩邊；舞台可以並排放兩個方案，但演其中一個時，另一個在 keyframe 裡調暗或收起。最後一段才並排比較，總結卡用對照表（`table`）列出各面向誰比較好，再附開會可以討論的問題（`questions`），讓與會者帶著問題離開，而不是只看到結論。
2. **從範例開始**：把 `assets/example-bubble-tea.html` 複製到交付位置，改名為 `<名稱>.src.html`。它已經接好播放器外框與控制列，換掉舞台和劇本就好。範例裡的 `<script src="player.js">` 只在 skill 目錄裡有效；複製到別處後，改成指向 `assets/player.js` 的相對路徑，否則直接打開 `.src.html` 會壞（產出的單一檔不受影響）。
3. **蓋舞台**：照真實產品的樣子畫，淺色、深色兩種配色都要有（範例已示範）。示範對象有現成 repo 時，照它的配色、字體、元件樣式畫，新元件要看起來像同一個產品做的，不自創風格。每個劇本會用到的元素都掛 `data-demo`。
4. **寫狀態與 render**：先列出畫面會變的所有東西（目前在哪一頁、選了什麼、輸入框寫了什麼），寫成 `initialState`；再寫 `render`。
5. **寫劇本**：欄位與規則見 `references/script-format.md`，寫之前先讀。重點是一步只有一個焦點；畫面的任何改變都寫進 `set`；點完會換頁就用 `after`。
6. **產出單一檔案**：
   ```bash
   python <skill>/scripts/inline_player.py <名稱>.src.html
   ```
   會產出 `<名稱>.html`，播放器已經塞進去了，傳給別人只要這一個檔。`.src.html` 留著之後改劇本用。
7. **驗收**：
   ```bash
   uv run --with playwright python <skill>/scripts/check_demo.py <名稱>.html
   ```
   會在三種視窗大小下逐格檢查，再用 2 倍速實際播一遍，並把截圖存到 `<名稱>-shots/`。再加 `--dark` 跑一次深色模式（舞台變深色、播放器變米白，頁面 CSS 的寫法見參考文件「深色模式」）。有任何一項不符就修到全過；再挑幾張截圖親眼看，確認畫面真的看得懂。預設借用系統的 Edge；沒有 Edge 時加 `--browser chromium`，並先執行 `uv run --with playwright playwright install chromium`。安裝套件失敗時，先檢查內部套件來源有沒有被 proxy 擋掉。

## 回報

交付時告訴使用者：檔案位置、有幾段、怎麼操作（舞台下方控制列的按鈕，或鍵盤 → ← 空白鍵 Esc）、驗收結果，以及沒做到或刻意省略的部分。

## 不要做的事

- 不要把 `player.js` 改成 `type="module"`：瀏覽器會擋從本機檔案載入 module，雙擊打開就壞。
- 不要在劇本裡寫座標，一律用 `data-demo` 名字。
- 不要把控制項浮在舞台上，也不要另做側邊面板；用播放器內建、接在舞台下方的控制列。
- 播放器有 bug 或缺功能時，改 `assets/player.js` 這份正本，不要只改某一份成品裡被塞進去的那份。
