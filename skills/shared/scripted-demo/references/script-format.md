## 建立播放器

```js
var demo = ScriptedDemo.create({
  stage: '#stage',            // 舞台：被示範的畫面；播放器把游標、spotlight 疊在它上面
  controls: '#tour-controls', // 控制列放哪：舞台正下方的空 div，播放器會把控制列畫進去（淺色模式是深色控制列，深色模式是米白）
  initialState: { ... },      // 進導覽前、也是每段 keyframe 的底
  theme: 'light',             // 選填：一打開是 'light'（預設）還是 'dark'
  device: 'desktop',          // 選填：被示範的是電腦畫面 'desktop'（預設）還是手機畫面 'phone'
  render: function (state, stage) { ... },
  sections: [ ... ]
});
```

`create` 也會設定 `window.__scriptedDemo`，給 `scripts/check_demo.py` 用，不要刪。

## 手機畫面

被示範的是手機 App 或手機版網頁時，`create` 加 `device: 'phone'`，舞台照手機的大小畫。完整寫法見 `../assets/example-bubble-tea-phone.html`。

- 舞台本身就是手機螢幕：寬 390px、高最多 844px（一般手機的大小），置中放在播放器外框裡，外面一圈深色 `border` 當手機外殼。控制列照樣接在下面，跟電腦版一樣寬。
- 游標換成手指點的半透明圓點，點在目標正中間；電腦版那種「小目標改指右下角外側」的規則不套用，因為手指本來就會蓋住按鈕。
- 觀眾常直接用手機打開 demo：頁面加 `@media (max-width: 520px)`，把手機外殼拿掉、舞台滿版（範例已寫好）；控制列在窄螢幕會自己改成章節左右滑、旁白和播放鈕上下排。
- 手機沒有滑鼠，劇本不要用 `do: 'hover'`；原本要 hover 才看得到的說明，改成點一下展開，或用 `point` 指過去。
- 手機畫面高度有限，最小視窗（1024x640）下舞台只剩約 440px 高。一個畫面放不下時，先精簡版面；真的要捲動，就在 `render` 裡把那個區塊捲到目標的位置。
- 驗收時 `check_demo.py` 看到 `device: 'phone'`，會另外用手機大小 390x844 再測一遍。

## 段落（section）

一段是一個完整的小故事，例如「第一次點餐」「改主意」「結帳」。播放器把每段展開成「介紹卡 → 各步 → 總結卡」。

| 欄位 | 必填 | 說明 |
|---|---|---|
| `title` | 是 | 段落名稱，出現在控制列的章節按鈕、旁白、卡片上 |
| `intro` | 否 | 一兩句話：這段要示範什麼。有寫才會出現介紹卡。字串裡的 `\n` 會換行，可以分成「要解決什麼」「在哪裡看到」兩行 |
| `keyframe` | 否 | 這段開頭的狀態，會蓋在 `initialState` 上。上一步、跳段都從這裡重算 |
| `steps` | 是 | 步驟陣列 |
| `summary` | 否 | 總結卡。`points` 列重點；`pros`／`cons` 列好處與要注意的地方；`table: { cols: [...], rows: [[...]] }` 做對照表；`questions` 列可以討論的問題；可加 `title`。比較設計方案時用 `table` 加 `questions` |

keyframe 要能獨立成立：只看 keyframe 就知道這段開頭畫面長怎樣，不依賴上一段演完的結果。這樣觀眾可以直接點任何一段開始看。

## 步驟（step）

| 欄位 | 必填 | 說明 |
|---|---|---|
| `target` | 是 | 游標要去的元素，填 `data-demo` 的名字（不是 selector、不是座標） |
| `focus` | 否 | spotlight 框哪個元素；預設就是 target。要框住整排選項時用它，target 必須在 focus 裡面 |
| `do` | 否 | `click`（預設）、`hover`、`type`、`point`（只移過去） |
| `text` | `type` 時 | 要打的字；打字動畫結束後，最終文字仍要寫在 `set` 裡 |
| `set` | 否 | 這一步做完後狀態改了什麼（只寫有變的欄位）。合併只有一層：巢狀物件要整包寫 |
| `after` | 否 | 這一步做完、畫面換了之後，游標和 spotlight 要移到哪個元素 |
| `afterFocus` | 否 | 搭配 `after`，spotlight 要框哪個元素；`after` 必須在它裡面 |
| `say` | 是 | 旁白，一句話，用觀眾的日常用語 |

上一步的原理：回到這段的 keyframe，瞬間套用前面各步的 `set`，再演這一步。所以**畫面的任何改變都必須寫進 `set`**；只在動畫裡做、沒寫進 `set` 的改變，按上一步或跳步時會消失。

## render 的約定

`render(state, stage)` 把狀態畫到舞台上，每次換步都會被呼叫：

- 只依 `state` 決定畫面：同樣的 state 一定畫出同樣的畫面。
- 切換 class、`hidden`、文字內容就好，不要整塊重建有 `data-demo` 的元素。重建會讓播放器正在演的 hover、按壓效果消失。
- 不要在 render 裡呼叫 `demo.update`，也不要啟動計時器。

## 轉場與節奏

轉場由播放器負責，劇本不用寫：

- 介紹卡 → 第一步：卡片淡出，spotlight 從游標尖端像光圈一樣張開，游標淡入。
- 最後一步 → 總結卡：spotlight 往游標收起，游標淡出，卡片淡入。
- 換段落（例如方案一 → 方案二）：舞台先暗到底、趁暗換成下一段的 keyframe，再亮起來，介紹卡從右邊滑進來。比較設計方案時，觀眾靠這個感覺到「換方案了」。

自動播放時，每一步停「1.5 秒＋旁白字數 × 40ms」，介紹卡停 2.8 秒，總結卡停 5 秒；都會依速度設定縮放。

## 自由操作

舞台本身可以點。事件處理器用 `demo.update({...})` 改狀態，跟劇本用同一個 `render`。導覽進行中 `update` 會被忽略，舞台也會停止接收點擊；觀眾按控制列的「自己點點看」或 Esc，導覽就停止，畫面回到導覽前的樣子。這顆按鈕由播放器提供，不用自己做分頁。

## 深色模式

播放器和舞台永遠一亮一暗，觀眾才分得出遙控器和節目：

| 模式 | 舞台 | 頁面外框與控制列 |
|---|---|---|
| 淺色（預設） | 亮色 | 深色（`#0b1220`） |
| 深色 | 深色 | Solarized Light 的米白（`#fdf6e3`） |

控制列上排「自己點點看」旁邊有一顆「☾ 深色／☀ 淺色」切換鈕，播放中切換也不會中斷導覽。播放器會在 `<html>` 加上 `data-sd-theme="dark"`（淺色時是 `"light"`），並自己換掉控制列、spotlight 暗色、卡片的配色。**頁面只要負責兩件事**：

1. 舞台換深色。照真實產品的深色版畫；產品有現成深色配色時照抄。
2. 頁面外框（`body` 或包住播放器的元素）換成米白，跟控制列同一色系。

最省事的寫法是把舞台顏色集中成 CSS 變數，深色模式只換這一組（範例就是這樣寫）：

```css
#stage { --bg: #fffaf3; --surface: #fff; --ink: #1f2937; background: var(--bg); color: var(--ink); }
[data-sd-theme="dark"] #stage { --bg: #282a36; --surface: #343746; --ink: #cecdda; color-scheme: dark; }
[data-sd-theme="dark"] body { background: #eee8d5; }
```

舞台已經寫死很多顏色時，就逐條寫 `[data-sd-theme="dark"] .某元件 { ... }` 覆寫。注意：

- `button` 預設不繼承文字顏色，要寫 `button { color: inherit; }`，否則深色舞台上的按鈕字會是黑的。
- 覆寫 `.a` 時，同樣特異度的 `.a.on`、`.a:hover` 也要一起寫，不然狀態色會被蓋掉。
- 深色舞台上的 tooltip 通常反過來用淺底，比較跳得出來。
- 頁面要用 JS 跟著換（例如畫布、圖表）時，聽 `window` 的 `sd-theme` 事件，`event.detail.theme` 是 `'light'` 或 `'dark'`；也可以直接呼叫 `demo.setTheme('dark')`、`demo.toggleTheme()`，目前模式在 `demo.theme`。

驗收時兩種模式都要跑：`check_demo.py <檔案>` 和 `check_demo.py <檔案> --dark`。加 `--dark` 會先切到深色再逐格檢查，舞台底色沒變也會報錯。

## 可以覆寫的樣式

- `--sd-bar`：淺色模式的控制列底色，預設 `#0b1220`；頁面外框建議用相近的深色，讓「深色是播放器、亮色是內容」一致
- `--sd-dim`：淺色模式下 spotlight 以外調暗的顏色，預設 `rgba(15,23,42,.55)`
- `--sd-accent`：淺色模式下 spotlight 外框與點擊漣漪的顏色，預設藍色
- `--sd-dark-bar`、`--sd-dark-dim`、`--sd-dark-accent`：深色模式的對應顏色，預設米白 `#fdf6e3`、`rgba(0,0,0,.45)`、淺藍 `#60a5fa`。深色舞台本來就暗，暗色疊太深（例如 .7）框外的字會讀不到；調整時拍同一格比較，確認框外的字還看得清楚、亮框也還分得出來。
- `.sd-hover`：`do: 'hover'` 時加在 target 上。原本靠 `:hover` 顯示的東西（例如 tooltip），要同時寫 `.sd-hover` 的版本，例如 `.info:hover .tip, .info.sd-hover .tip { display: block; }`
- `.sd-press`：點擊瞬間加在 target 上，可以做按下去的效果

## 規則與理由

`scripts/check_demo.py` 會用程式檢查這些規則：

1. **游標永遠在 spotlight 裡。** 觀眾的眼睛同時被亮的地方和游標拉住，兩者分開時，觀眾不知道該看哪裡。播放器讓兩者用同樣的時間一起移動，所以移動途中也成立。
2. **游標不出舞台。** 位置會被限制在舞台內。游標尖端預設對準目標中間；哪一軸小於 64px，尖端就移到那一側外面（寬太小移到右邊外、高太小移到下面外；icon 這種兩軸都小的就是右下角外側），箭頭才不會蓋住 icon。
3. **spotlight 跟著元素走，不寫死座標。** 視窗縮放、Ctrl +/-、版面變化之後都會即時重算。劇本只寫 `data-demo` 名字，就是為了這條。
4. **一步只有一個焦點。** 注意力要移到別處，就拆成下一步，或用 `after` 明確指定。例如按下「加入購物車」後畫面換頁，按鈕消失了，就要用 `after` 指到購物車清單。
5. **旁白不蓋住目標。** 有控制列時旁白寫在控制列裡，不疊在舞台上；沒有控制列時，spotlight 靠近舞台底部，旁白會自動移到頂端。
6. **停止後還原。** 進導覽前的狀態會被保存，停止時還原。

## 常見錯誤

| 症狀 | 原因 | 修法 |
|---|---|---|
| 雙擊打開，播放器沒反應 | `player.js` 被改成 `type="module"` | 用一般 `<script src>` |
| 按上一步後，某個東西不見了 | 那個改變沒寫進 `set` | 把它寫進該步的 `set` |
| 檢查說「找不到錨點」 | 點完後畫面換了，目標消失 | 加 `after` |
| tooltip 在導覽中不出現 | 只寫了 `:hover` | 補 `.sd-hover` 的選擇器 |
| spotlight 框到空白處 | 有地方用寫死的座標，或錨點掛錯元素 | 一律用 `data-demo`，掛在真正會被點的元素上 |
| 檢查說「被捲動容器切掉」 | 目標在可捲動區塊裡，只露出一部分 | 在 render 裡把那個區塊捲到目標的位置，或調整版面 |
| 總結卡內容很長 | 卡片超過舞台高度時會出現捲軸，但觀眾不一定會捲 | 精簡文字，最小視窗下也要一眼看完 |
| 加了 `hidden` 卻沒藏起來 | 同一個元素的 CSS 另外寫了 `display`，蓋掉了 `hidden` | 補 `.你的class[hidden] { display: none; }`；檢查腳本抓不到，要看截圖 |
| 連按下一步時動畫疊在一起 | 自己另外寫了動畫或計時器，沒用播放器的 `_wait` | 動畫交給播放器；真的要加，記得檢查世代計數 |
