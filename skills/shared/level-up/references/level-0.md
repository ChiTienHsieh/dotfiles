# Level 0：目標、講法、深度、媒介

開課前一定跑一次。這是使用者選擇的確認點：自己先在腦中排一下大概幾關、每關講什麼，足以給推薦就好，然後等使用者回答。使用者選好前不開始教。

## 白話原則

Level 0 是高中生也看得懂的一段話。禁用 carrying capacity、metaphor system、advisory 這類詞；每個選項一句話講完，不附「預測」「映射表」。推薦用 ★ 標在選項前面，理由一句。

## 問目標

一句開放式的問題，問學完要拿來做什麼，不是問主題。給幾個例子但不限制：看懂同事在講什麼、修好某個 bug、準備面試、純好奇。

目標比預設的心智模型優先：用它決定關卡順序、加關、砍關，每關結尾「對回你的情況」也接它。使用者說「直接教」或沒給目標，就用標準心智模型課，不卡住。

## 講法選項

類比不是必須。三個選項，A 固定是職場鬼故事並預設標 ★：

- **A ★ 職場鬼故事**：Ben（新人亂搞）、Jack（資深但大意）、David（收拾殘局）演真實事故，每關一個，講完對回你的情況。風格見 `teaching-style.md`。
- **B <類比世界>**：從 `learning/user-profile.md` 挑一個已驗證有效、能撐完整門課的世界；一句話說這個世界怎麼對到主題。整門課只用一個世界，不混。
- **C 直接講技術**：不套故事，一關一個概念，配一個最小例子。

只在 A 撐不住主題（例如純數學）時才把 ★ 移到別的選項，並說一句為什麼。B 的世界若不確定遊戲機制或年代事實，先查或先問，不憑印象講。

## 深度選項

- `1` 速成：知道正常路怎麼走、什麼情況該找人。
- `2` 打底：常見狀況跟地雷都能自己處理。
- `3` 深挖：連取捨跟例外都要搞懂。

## 媒介選項

- `m` 聊天：課跟題目都在聊天裡。
- `h` 網頁：課做成單一 HTML 檔，聊天只留簡介、絕對路徑、正式題目。
- `a` 先聊天：之後要換網頁會先問你。

依這門課實際的長相（有沒有大量比較、指令、圖）標一個 ★，理由一句。使用者檔案是參考，不是自動選 HTML 的理由。

## 收答案

請使用者回三個字：大寫講法＋深度數字＋小寫媒介，例如 `A2m`、`B1h`、`C3a`。推薦只是建議，不覆寫使用者的選擇，也不悄悄換媒介。

三個都選好才開始。簡短確認一句，靜默記下選擇與目標，然後照 `teaching-engagement.md` 建進度表、排關卡。之後想換媒介，先講清楚換了對下一關有什麼好處，再問。

## 範例

```markdown
學 SSH 之後想拿來幹嘛？例如：連 lab 的機器不用每次打密碼、看懂同事在講什麼、純好奇。

怎麼講：
A ★ 職場鬼故事：Ben 半夜連不上、Jack 把 key 丟錯台、David 收拾。每關一個事故，講完對回你的機器。
B 芙莉蓮：SSH 是通行證，key 是欣梅爾留給未來的信物。
C 直接講技術：一關一個概念，配指令。

多深：1 速成 / 2 打底 / 3 深挖

在哪看：m 聊天 ★（都是指令，聊天就夠） / h 網頁 / a 先聊天

回我像 A2m 這樣三個字就好。
```
