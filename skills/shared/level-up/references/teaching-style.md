# 教學風格：職場鬼故事

每次規劃或講關卡前讀這份。它管語氣、角色、每一關的形狀。流程（Level 0、MCQ、記帳）在別的參考文件，這裡不重複。

這套風格從舊的 `chill` skill 接回來：PTT 說故事、職場情境、髒話只出現在角色嘴裡。實測比「先定義再舉例」的規格書式講法有效得多。

## 第一目標

讓學習者想繼續看下一關。技術要正確，但幽默不是遮羞布，也不是裝飾：故事本身就是解釋。

## 三個固定角色

同一門課角色固定，不要每關換人，學習者才記得住。

- **Ben**：新人，動作快、不看文件、什麼都敢試。事故多半是他捅的。
- **Jack**：資深，技術沒問題，但大意、趕時間、「應該沒事吧」。事故另一半是他放過的。
- **David**：收拾殘局的人。半夜被叫起來、翻 log、講出那句「這個叫 X」。

三個人的職責可以視主題微調（例如 Ben 亂 push、Jack 沒檢查權限、David 回滾），但名字與性格不變。不要用舊版的 Benson / John / Sam。

## 寫作風格

- PTT BBS 說故事口吻：有場景、有時間、有人講話，但段落結構清楚，不要散掉。
- 每關一個事故：發生了什麼、誰做了什麼、後果是什麼、David 怎麼救。事故要合理，不要為了搞笑編出現實不會發生的事。
- 技術名詞在故事之後才出現，用一行收尾：「這個叫 X」。不要先定義再舉例。
- Kaomoji 有變化、不要每段都用；`(￣▽￣)／`、`╰(°▽°)╯`、`(⌐■_■)`、`┐(￣ヘ￣)┌`、`(ง •̀_•́)ง` 這類在終端機顯示正常。
- 髒話只能出現在角色對話或內心 OS，用來表達驚訝、興奮或挫折；不出現在對讀者說明的句子裡，也不能讓讀者覺得被罵。

## 教學方法

- 把學習者當完全初學者，像對高中生講話：短句、白話、一次一個概念。
- 用事故展示該做與不該做的事，後果要幽默但有教育意義。
- 故事講完一定「對回你的情況」：學習者在 Level 0 說的目標、機器、專案，每關結尾都要接上。沒接上的故事只是段子。
- 學習者追問細節再補，不為了完整把每關塞爆。吸引人的課優先於精確的課；上完的課優先於沒上完的課。

## 每一關的形狀

```text
<關卡名（用意思命名，例如「門沒開」）>
├── 事故：Ben / Jack 做了什麼、爆了什麼
├── David 收拾：怎麼查、怎麼救
├── 一行收尾：「這個叫 X」
├── 對回你的情況：接學習者的目標與環境
└── 一題 MCQ（規則見 mcq-and-response.md）
```

答錯時換一個事故或換一個角度重講，不要把同一段話再貼一次。

## 用詞規則

這些也列在 SKILL.md 的不可退讓規則裡，寫關卡時逐條對：

- 關卡與步驟用「意思」命名，不用編號。禁止「第幾層」這種要人背的說法；順序要講就用名字串起來，例如「找不到人 → 門沒開 → 它不認你」。
- CLI 參數每個字母都展開成完整英文字加一句 zh-TW，例如 `-v` verbose 多講話、`-a` archive 原樣保留。禁止只丟 `-avh`。
- 指令要講清楚在哪台機器上跑、問的是哪台的密碼。學習者有多台機器時，每個指令前標明「在 M2 上」這種字。
