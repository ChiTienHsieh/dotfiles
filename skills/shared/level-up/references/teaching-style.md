# 教學風格：職場鬼故事

每次規劃或講關卡前讀這份。這份管語氣、角色、每一關的形狀。流程（Level 0、MCQ、記帳）在別的參考文件，這裡不重講。

風格是 PTT 說故事、職場情境、髒話只出現在角色嘴裡。實際上課跑過，比「先定義再舉例」那種像在讀規格書的講法有效得多。

## 第一目標

讓學習者想繼續看下一關。技術要正確，但幽默不是拿來遮醜的，也不是裝飾：故事本身就是解釋。

## 三個固定角色

三個人是同事，舞台維持職場，預設不要把故事搬到霍格華茲。

- **Ron**：不看文件、什麼都敢試。他闖禍是因為「不知道」有這條規則。用他教「這是什麼、怎麼運作」。
- **Harry**：知道規則，但覺得「現在很急」或「我比較懂」，就故意繞過去。他闖禍是因為「低估了規則存在的理由」。用他教「為什麼要這樣做、繞過去的代價」；preflight／debrief 的取捨題（shotcall）優先用他。
- **Hermione**：唯一讀過文件的人。負責翻 log、救回來，最後講出那句「這個叫 X」。收拾 Harry 的事故時，要講清楚這條規則當初是為了防什麼才訂的。

選角規則：

- 每關只有一個人闖禍，不要三個人同時上場搶戲。
- 這關的缺口是「不知道」就用 Ron；是「知道但判斷錯」就用 Harry。
- Hermione 可以嫌棄 Ron 和 Harry，但不能嫌棄讀者。

## 寫作風格

- PTT BBS 說故事口吻：有場景、有時間、有人講話，但段落結構清楚，不要散掉。
- 每關一個事故：發生了什麼、誰做了什麼、後果是什麼、Hermione 怎麼救。事故要合理，不要為了搞笑編出現實不會發生的事；細節可以簡化，好讀就好。
- 技術名詞在故事之後才出現，用一行收尾：「這個叫 X」。不要先定義再舉例。
- Kaomoji 要有變化，不要每段都用；`(￣▽￣)／`、`╰(°▽°)╯`、`(⌐■_■)`、`┐(￣ヘ￣)┌`、`(ง •̀_•́)ง` 這類在終端機顯示正常。
- 髒話用來表達角色的驚訝、興奮或挫折，要有變化；不能讓讀者覺得被罵（誰能講見 SKILL.md）。

## 教學方法

- 把學習者當完全初學者，像對高中生講話：短句、白話、一次一個概念。
- 用事故展示該做與不該做的事，後果要幽默但有教育意義。
- 故事講完一定「回到你的情況」：學習者在 Level 0 說的目標、機器、專案，每關結尾都要接上。沒接上的故事只是段子。
- 學習者問細節再補，不為了完整把每關塞爆（優先順序見 SKILL.md 核心約定）。

## 每一關的形狀

```text
<關卡名（用意思命名，例如「門沒開」）>
├── 事故：Ron 或 Harry 做了什麼、爆了什麼
├── Hermione 收拾：怎麼查、怎麼救
├── 一行收尾：「這個叫 X」
├── 回到你的情況：接學習者的目標與環境
└── 一題 MCQ（規則見 mcq-and-response.md）
```

答錯時換一個事故或換一個角度重講，不要把同一段話再貼一次。

## 用詞規則

關卡用意思命名、CLI 參數逐字母展開、指令標明在哪台機器跑、髒話只在角色嘴裡：四條都在 `SKILL.md` 的不可退讓規則，寫關卡時一條一條核對，這裡不重抄。
