description: 更新 task／session 標題。當使用者要求 name／rename task、送出最後回覆前 task 到達有意義的等待、理解或完成節點（一般 turn 結束不改名），或 Chief of Staff／排程工作要整理標題時使用。
---

只有標題能幫助使用者看出下一步行動或應理解內容時才更新。

## 流程

1. 讀取 task 的最新狀態。若要替其他 task 改名，就在改名前重新讀取該 task。
2. 若準備把任一 task 標題開頭的狀態 emoji 改為 `📦`：
   - 若處理目前 task，從目前可用的 skills 清單取得名稱精確為 `wrap` 的唯一項目，完整讀取其 `SKILL.md`，只執行其中的「封存前檢查」流程；找不到、不唯一或缺少該流程時停止，檢查通過才可繼續。
   - 若處理其他 task，不得沿用目前 task 的檢查結果；只有重新讀取後確認該 task 的同等封存前檢查已通過，才可使用 `📦`。
3. 每個標題只放一個開頭 emoji，先判斷處置狀態，再選用途或主題：
   - `🧑`：有明確待 human 決定、確認或執行的事項；不使用「等我／等你」描述責任。
   - `💤`：已明確暫放；閒置或久未更新不等於暫放。
   - `📦`：通過步驟 2 的檢查，沒有未完成責任或重要學習，值得封存。
   - 沒有上述處置狀態時：`🤖` 表示 Codex 建立的獨立委派 task，`📚` 表示學習對話；同時符合時用 `🤖`，主題寫出學習目的。一般 human 開啟的 task 不因 agent 參與而變成委派 task。
   - 其他情況可用 domain emoji 表示長期 workstream，例如 `🏠` 買房；沒有 App 分組的環境也保留這種辨識方式。
   - `🤖` 不表示正在執行；不用 `⏳` 重複工具等待或 App 的活動指示。內建 subagent 不為了標題另開 sidebar task。
   - 重要性與期限交給排序及必要文字；Pin 與標題 emoji 分開判斷，只由使用者明示新增或解除，不因重新分類自行改 pin。
4. 若 agent 應繼續工作且使用者無須行動，不例行改名；但原有 `🧑`／`💤`／`📦` 已不符合最新內容時，改回用途或主題 emoji。不要為每次工具審核改名。Stop、閒置、最後回覆或只有本機 commit，都不足以使用 `📦`。
5. 開頭 emoji 只是辨識標記，不是完整標題。只變更 emoji 時，替換開頭既有 emoji；若沒有，就在最前面插入。保留仍然準確的主題；使用者轉換主要目的時才更新範圍。不得把完整標題縮成單一 emoji。
6. 新增標題或完整改名時，優先用短中文表達最小可辨識主題：

   ```text
   <一個 emoji> <主題>〔｜待辦或必要狀態〕
   ```

   方括號表示可省略，不寫進標題。通常一行、最多一個 `｜`；不設最低字數，能辨識就停。只有狀態會改變使用者下一步時才加上，例如「待登入」或「待選規則」，不例行附上「進行中／已完成」。主題要能區分同專案的不同工作，讓不了解內部 schema、tab 名稱或 agent workflow 的使用者也看得懂；不塞入 prompt、路徑或委派指令，也不為了分類而重複分組名稱。

   保留有辨識力的專案名與必要英文，其餘優先中文；只沿用使用者已指定的縮寫。Pilates 主題使用「皮」，一般主題 emoji 用 `🧘`；處置或用途 emoji 優先，例如「🧘 皮彈簧設定」；個人評測可寫「🧑 個人評測集｜待選規則」。這些縮寫只用於標題，不改專案、程式碼或檔案名稱。

7. 套用標題：執行 `scripts/rename-session.sh "<title>"`。若你的執行環境有原生改標題工具（見下方），優先使用原生工具。各環境的細節與注意事項在 `runtimes/<環境>.md`。

   - Codex App：使用 `set_thread_title` tool（不需要 script）
   - tmux 環境（`$TMUX_PANE` 已設定）：只有目前 human 指令明確要求改名，才可執行 script 送出 `/rename`；自動觸發本 skill 不構成授權，否則只提供建議標題。
   - 非 tmux 環境：script 會印出建議標題，由使用者用 `/rename` 套用

   每項工具只呼叫一次。目前 task 省略 `threadId`；經授權替其他 task 操作時，使用步驟 1 取得的精確 ID 與 host。標題與 pin 是兩項獨立資訊，不要為了讓兩者看起來一致而自行新增或解除 pin；任何一項失敗時，重新讀取實際狀態並回報，不得盲目重試。

8. 缺少哪項工具，就明講該項仍需手動完成。不得重建舊 Stop hook、shell、app-server 或暫存檔等替代方案。

本 skill 只負責標題，以及使用者明示的 pin／unpin；不得藉此封存、取消封存、刪除或改變其他 task 的狀態。`📦` 只代表建議使用者之後封存；若其他 workflow 已取得使用者明示的封存授權，由該 workflow 執行。

只在使用者單獨要求改名時簡短確認；作為其他工作的正常收尾時不另行報告。
