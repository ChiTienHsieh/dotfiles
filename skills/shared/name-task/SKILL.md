---

只有標題能幫助使用者看出下一步行動或應理解內容時才更新。

## 流程

1. 讀取 task 的最新狀態。若要替其他 task 改名，就在改名前重新讀取該 task。
2. 若準備把任一 task 標題開頭的狀態 emoji 改為 `📦`：
   - 若處理目前 task，從目前可用的 skills 清單取得名稱精確為 `wrap` 的唯一項目，完整讀取其 `SKILL.md`，只執行其中的「封存前檢查」流程；找不到、不唯一或缺少該流程時停止，檢查通過才可繼續。
   - 若處理其他 task，不得沿用目前 task 的檢查結果；只有重新讀取後確認該 task 的同等封存前檢查已通過，才可使用 `📦`。
3. 選擇能讓使用者最快辨識 task 的開頭 emoji：
   - 可用 domain emoji 表示長期 workstream，例如 `🏠` 買房。domain emoji 通常比暫時狀態更有辨識力時，優先保留 domain emoji。
   - `🚨` 只表示真的緊急或需要近期處理，不等同於 pin。
   - `⏳` 適合沒有更有用 domain emoji、且下一步需要使用者行動的 task。
   - `📦`：沒有未完成責任或重要學習，值得封存。
   - Pin 是「使用者目前要持續注意」的唯一依據，與標題 emoji 分開判斷；只由使用者明示新增或解除。若 task 進入重要或長期狀態而尚未被 pin，可順帶建議使用者 pin，但不代為執行。
4. 若 agent 應繼續工作且使用者無須行動，不改名。Stop、閒置、最後回覆或只有本機 commit，都不足以使用 `📦`。
5. 開頭 emoji 只是辨識標記，不是完整標題。只換 emoji 時，替換開頭既有的 emoji，沒有就插在最前面；主題照舊，使用者換了主要目的才改主題。每次動標題都順手重看「｜」後那段：使用者不用再做那件事就拿掉。不得把標題縮成只剩 emoji。
6. 新標題或完整改名用短中文，寫到能認出是哪件事就停：

   ```text
   <一個 emoji> <主題>〔｜待使用者做的事〕
   ```

   〔〕裡的可省略，括號本身不寫。一行、最多一個 `｜`，不設最低字數。只有要等使用者做某件事時才加「｜待…」，例如「待登入」「待選規則」；不例行寫「進行中／已完成」。主題要分得出同專案的不同工作，不懂內部 schema、tab 名稱或 agent workflow 的人也看得懂；不塞 prompt、路徑或委派指令。專案名和必要的英文保留，其餘用中文；縮寫只用使用者自己講過的，而且只出現在標題，不改專案、程式碼或檔案名稱。

7. 套用標題：有原生改名工具就用；沒有就執行 `scripts/rename-session.sh "<title>"`；都不行就給使用者建議標題。細節見 `runtimes/<環境>.md`。

   - Codex App：使用 `set_thread_title` tool（不需要 script）
   - tmux：script 對自己的 `$TMUX_PANE` 送出 `/rename <title>`（授權範圍見 `agents/AGENTS.md`）。
   - 非 tmux 且沒有原生工具：script 印出建議標題並以 exit 1 結束，由使用者自己改名。

   每項工具只呼叫一次。目前 task 省略 `threadId`；經授權替其他 task 操作時，使用步驟 1 取得的精確 ID 與 host。標題與 pin 是兩項獨立資訊，不要為了讓兩者看起來一致而自行新增或解除 pin；任何一項失敗時，重新讀取實際狀態並回報，不得盲目重試。

8. 缺少哪項工具，就明講該項仍需手動完成。不得重建舊 Stop hook、shell、app-server 或暫存檔等替代方案。

本 skill 只負責標題，以及使用者明示的 pin／unpin；不得藉此封存、取消封存、刪除或改變其他 task 的狀態。`📦` 只代表建議使用者之後封存；若其他 workflow 已取得使用者明示的封存授權，由該 workflow 執行。

只在使用者單獨要求改名時簡短確認；作為其他工作的正常收尾時不另行報告。
